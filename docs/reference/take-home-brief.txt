               Product context
               Autumn’s customer is not a growth marketer.
               They are usually an owner-operator of an independent hotel, inn, B&B, ranch,
               lodge, or boutique property. They may be the front desk, the marketing
               department, the revenue manager, and the person fixing the towel rack, all in the
               same day.
               They care about questions like:
                • Did Autumn help me get more direct bookings?
                • How much revenue did that create?
                • Are the right guests finding my property?
                • What changed since last month?
                • Is anything concerning?
                • What is Autumn doing about it?

               Requirements
               1. Build two connected screens

               You may use any styling system, charting library, user interface (UI) library, or
               backend approach you think is appropriate, as long as the final result is polished,
               fast, and reliable.

               3. Seed your own database
               Create and seed a hosted database with at least 720 days of plausible, meaningful
               marketing data.
               Free-tier infrastructure is completely fine. Examples include Supabase, Neon,
               MongoDB, or another hosted database you prefer.
               Your data model is part of the assignment. It should generally represent the kind of
               information in the reference dashboard, but it should not be random noise. The
               data should feel realistic for an independent hotel marketing program.
               Your seeded data should support both screens. If the dashboard shows
               seasonality, campaign performance, feeder markets, bookings, revenue, visitor
               behavior, or trend comparisons, the underlying data should make those views
               believable.
               A seeding script is a positive signal. We want to see how you think about data
               shape, data quality, and repeatable setup.

               4. Design for hotel owners
               The redesigned dashboard should be less intimidating and less overwhelming than

                • What the user should see first
                • What belongs on the main screen
                • What belongs on the second screen
                • Which metrics deserve emphasis
                • Which metrics need plain-language explanation
                • Which details should be available but not dominant
